02 — Clasificación: predicción de un resultado binario

Estimaremos si un cliente abandona el servicio mediante datos generados. La lección relaciona la verosimilitud de Bernoulli con estimaciones de probabilidad y, después, con una regla de decisión elegida por separado; no describe clientes reales.

Sigmoide y umbral de decisión ilustrativos. Una probabilidad continua y una acción discreta son resultados distintos.

Una puntuación, una probabilidad y una decisión

La sigmoide es $\sigma(z)=1/(1+e^{-z})$. Un logit $z=\log 3$ da la probabilidad $p=0.75$. Para una observación positiva, su log-verosimilitud negativa es $-\log(0.75)\approx0.288$, y la derivada respecto del logit es $p-y=-0.25$. En código, evalúa la pérdida logística como np.logaddexp(0, z) - y*z en vez de formar exponenciales que pueden ser inestables.

fit(X, y) aprende coeficientes a partir de las filas y sus etiquetas. predict_proba(X_new) devuelve probabilidades en el orden indicado por classes_, así que revisa ese atributo antes de suponer qué columna corresponde a la clase positiva. predict(X_new) convierte las puntuaciones en etiquetas usando el umbral predeterminado del estimador, normalmente 0.5 en regresión logística binaria. Cambiar el umbral de decisión cambia la acción, no la probabilidad ajustada.

Si se señalan 10 personas y 6 abandonan el servicio, la precisión es 6/10. Si 8 personas abandonan en total, la exhaustividad es 6/8. Los conteos de la matriz de confusión son VP=6, FP=4 y FN=2; el número de VN depende del tamaño total de la población. La calibración plantea otra pregunta: entre muchos casos a los que se asigna una probabilidad cercana a 0.75, ¿el resultado es 1 en aproximadamente el 75 %? Un buen ordenamiento no garantiza una buena calibración.

1. Verosimilitud de Bernoulli y optimización convexa

Con predictor lineal $\eta_i=\beta_0+x_i^T\beta$ y $p_i=\sigma(\eta_i)$, la verosimilitud de Bernoulli es $p_i^{y_i}(1-p_i)^{1-y_i}$. La log-verosimilitud negativa por observación es

$$\ell_i(\beta)=\log(1+e^{\eta_i})-y_i\eta_i,$$

y el riesgo empírico es $L(\beta)=n^{-1}\sum_i\ell_i(\beta)$. Al derivar mediante $p_i=\sigma(\eta_i)$, se obtiene el gradiente respecto de las pendientes $X^T(p-y)/n$ y la Hessiana $X^TWX/n$, donde $W_{ii}=p_i(1-p_i)\ge0$. La Hessiana es semidefinida positiva, por lo que la pérdida logística es convexa. Añadir $\lambda\|\beta\|_2^2/2$ suma $\lambda\beta$ al gradiente y $\lambda I$ al bloque de pendientes de la Hessiana. Una penalización positiva vuelve definido positivo ese bloque. Por convención, el intercepto no se penaliza; scikit-learn lo trata por separado.

3. Entrenamiento, validación y prueba final

Reservamos el 20 % de las observaciones para una prueba final. El resto de los datos de desarrollo se divide en conjuntos de entrenamiento y validación. 4. Pipeline para entradas mixtas

Escala las características numéricas y codifica el tipo de contrato con indicadores one-hot. Codificar categorías como enteros sugeriría un orden artificial. Todas las transformaciones forman parte del pipeline, por lo que la validación cruzada vuelve a ajustarlas dentro de cada partición.

Python · ejecutar en el cuaderno
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

numeric_columns = ["tenure_months", "monthly_charge", "support_calls"]
categorical_columns = ["contract"]

numeric_preprocessing = Pipeline(
    steps=[
        ("impute", SimpleImputer(strategy="median")),
        ("scale", StandardScaler()),
    ]
)
categorical_preprocessing = Pipeline(
    steps=[
        ("impute", SimpleImputer(strategy="most_frequent")),
        ("one_hot", OneHotEncoder(handle_unknown="ignore")),
    ]
)
preprocessing = ColumnTransformer(
    transformers=[
        ("numeric", numeric_preprocessing, numeric_columns),
        ("category", categorical_preprocessing, categorical_columns),
    ]
)
classification_pipeline = Pipeline(
    steps=[
        ("preprocessing", preprocessing),
        ("model", LogisticRegression(max_iter=2000)),
    ]
)

5. Regularización con las filas de entrenamiento

La derivación expresa la pérdida logarítmica negativa media más una penalización de las pendientes $\lambda\|\beta\|^2/2$. Para la implementación lbfgs instalada con filas sin ponderar, la lambda equivalente es $1/(Cn)$; con pesos de clase o de muestra, se sustituye $n$ por la suma de los pesos. Así, C es la intensidad inversa de regularización y su relación numérica con lambda depende del número de filas de ajuste. La validación cruzada estratificada elige C usando las filas de entrenamiento; la validación se reserva para definir la política del umbral y la prueba final permanece intacta.

Interpretar la configuración del clasificador a partir de la verosimilitud

El preprocesamiento transforma las filas originales en coordenadas numéricas; la regresión logística asigna a cada fila un logit lineal y aplica la sigmoide. La tabla resume las opciones usadas; la página oficial de la API documenta otros solvers y penalizaciones.

Objeto o parámetro Valor usado Efecto y compromiso
SimpleImputer mediana para las columnas numéricas; categoría más frecuente para el contrato Aprende los valores de reemplazo con las filas de ajuste. La ausencia de datos no se modela como un efecto independiente.
StandardScaler centrar y escalar las columnas numéricas Hace que la penalización L2 actúe en escalas numéricas comparables y favorece una optimización estable.
OneHotEncoder handle_unknown="ignore", drop=None Codifica las categorías de contrato sin imponerles un orden artificial. La regularización L2 controla la redundancia entre el intercepto y los indicadores de categoría.
LogisticRegression penalty="l2", solver="lbfgs", fit_intercept=True, max_iter=2000 Ajusta la verosimilitud de Bernoulli con penalización en las pendientes. El intercepto no se penaliza. Un límite mayor de iteraciones permite converger, pero no resuelve la separación ni un escalado deficiente.
C y GridSearchCV C en [0.03, 0.1, 0.3, 1, 3, 10]; 5 particiones estratificadas; ROC-AUC; refit=True C es la inversa de la intensidad de regularización: un C menor implica más contracción. La búsqueda selecciona el rendimiento de ordenamiento en las particiones de entrenamiento y luego reajusta el modelo con todas las filas de entrenamiento.

Para la implementación lbfgs , con datos sin ponderar se usa la convención $\text{mean Bernoulli loss}+\|w\|_2^2/(2Cn)$, donde $n$ es el número de filas de ajuste y el intercepto queda excluido de $w$. Por tanto, en este caso sin ponderar, la $\lambda$ de la derivación corresponde a $1/(Cn)$. Con pesos de muestra o de clase, la implementación usa la suma total de esos pesos en este escalado. La relación muestra por qué C cambia con el tamaño de los datos cuando se expresa el objetivo con pérdida media. Consulta la referencia oficial de LogisticRegression, Pipeline, y OneHotEncoder para ver las referencias.

6. Métricas de validación antes de elegir un umbral

Con umbral 0.5, la exactitud es la proporción de decisiones correctas. La precisión es la proporción de clientes señalados que realmente abandonan el servicio; la exhaustividad es la proporción de quienes lo abandonan que se detecta. Su media armónica es $F_1=2PR/(P+R)$. ROC-AUC es la probabilidad de que una persona positiva elegida al azar reciba una puntuación mayor que una negativa elegida al azar, contando los empates como medio. Mide el ordenamiento, no la calibración de probabilidades ni una política concreta.

El umbral 0.5 predeterminado sirve como referencia, no como política universal. Esta sección informa las métricas de validación con umbral 0.5 y frente a una línea base de la clase mayoritaria. La partición final de prueba sigue intacta.

Python · ejecutar en el cuaderno

    accuracy_score,
    confusion_matrix,
    f1_score,
    precision_score,
    recall_score,
    roc_auc_score,

validation_probabilities = best_classifier.predict_proba(validation_features)[:, 1]
validation_predictions_at_half = (validation_probabilities >= 0.5).astype(int)

majority_baseline = DummyClassifier(strategy="most_frequent")
majority_baseline.fit(training_features, training_response)

print("Validation majority-baseline accuracy:",

print("Validation metrics at threshold 0.5:", {

    "ROC-AUC": round(roc_auc_score(validation_response, validation_probabilities), 3),
})
print("Validation confusion matrix [actual rows, predicted columns]:\n",
      confusion_matrix(validation_response, validation_predictions_at_half))

Inspeccionar los conteos de validación y la calibración de probabilidades

Las filas de la matriz de confusión son las clases reales; las columnas, las predichas. La calibración compara la probabilidad predicha media con la fracción observada de positivos dentro de cada intervalo. La diagonal discontinua representa la calibración ideal. El número de casos por intervalo importa: uno pequeño puede alejarse de la línea por variabilidad muestral. Este diagnóstico usa validación; no ajusta una calibración nueva ni toma decisiones a partir de la prueba.

7. Elegir un umbral con validación y luego evaluar una vez en prueba

Supongamos que un falso positivo tiene costo $C_{FP}$ y un falso negativo, costo $C_{FN}$; las decisiones correctas tienen costo cero. Si la probabilidad $p$ está calibrada, predecir abandono cuesta en promedio $C_{FP}(1-p)$, mientras que predecir permanencia cuesta $C_{FN}p$. Se elige abandono cuando

$$C_{FP}(1-p)\le C_{FN}p\quad\Longleftrightarrow\quad p\ge\frac{C_{FP}}{C_{FP}+C_{FN}}.$$

Este umbral supone que las probabilidades están calibradas para la población donde se tomarán las decisiones, que los costos son conocidos y constantes, y que las decisiones no comparten una restricción de capacidad. Usaremos la razón hipotética $C_{FP}=1$, $C_{FN}=5$, que da un umbral teórico $1/6\approx0.167$. Revisamos varios umbrales en los datos de validación para observar el compromiso en una muestra finita y elegimos el de menor costo estimado. Luego fijamos el umbral y evaluamos una sola vez el conjunto de prueba. Estos costos ilustrativos no describen una intervención real.

Python · ejecutar en el cuaderno
import matplotlib.pyplot as plt
from sklearn.metrics import RocCurveDisplay

RocCurveDisplay.from_predictions(validation_response, validation_probabilities)
plt.title("Validation ROC curve")
plt.show()

false_positive_cost = 1.0
false_negative_cost = 5.0
threshold_candidates = [0.10, 0.17, 0.25, 0.35, 0.50, 0.65]
threshold_results = []

for threshold in threshold_candidates:
    validation_decisions = (validation_probabilities >= threshold).astype(int)
    true_negative, false_positive, false_negative, true_positive = confusion_matrix(
        validation_response, validation_decisions, labels=[0, 1]
    ).ravel()
    estimated_cost = (false_positive_cost * false_positive
                      + false_negative_cost * false_negative)
    threshold_results.append(
        {
            "threshold": threshold,
            "flagged": int(validation_decisions.sum()),
            "false_positives": false_positive,
            "false_negatives": false_negative,
            "estimated_cost": estimated_cost,
        }
    )

validation_cost_table = pd.DataFrame(threshold_results)

8. Coeficientes como asociaciones condicionales de log-odds

Un coeficiente cambia los log-odds ajustados en esa cantidad cuando una variable aumenta una unidad —o una desviación estándar si se trata de una variable numérica escalada—, condicionando por las demás entradas codificadas. Al exponenciarlo se obtiene una razón de momios del modelo. Las razones de momios no son razones de riesgo, y los coeficientes observacionales no establecen causalidad.
