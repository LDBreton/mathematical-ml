Proyecto final del curso

Elige un problema de las lecciones 01–07 y convierte la lección en un experimento justificado de forma independiente. El propósito es conectar las matemáticas con los supuestos, el código y la evaluación. Usa los datos sintéticos proporcionados o un conjunto público aprobado por el docente y con procedencia documentada. No recopiles registros privados para este trabajo.

Informe requerido

  1. Problema e información: define la respuesta, la unidad de predicción, la decisión prevista y la información disponible al predecir. Para agrupamiento, define la geometría y la interpretación prevista en lugar de inventar una variable objetivo.
  2. Modelo matemático: escribe la función objetivo y explica cada término. Deriva al menos una actualización, gradiente, proyección o regla de decisión. Distingue los supuestos del modelo de las conclusiones que realmente se desprenden de ellos.
  3. Datos y validación: documenta el esquema, las unidades, la procedencia, los valores faltantes y la estructura de muestreo. Justifica la partición independiente, por grupos o cronológica. Indica qué observaciones se usan para preprocesar, seleccionar parámetros, elegir umbrales y evaluar finalmente.
  4. Modelo de referencia y modelo: construye una referencia transparente y al menos una alternativa justificada. Para agrupamiento, compara un conjunto predefinido de números de grupos o geometrías. Mantén las transformaciones aprendidas junto al estimador cuando corresponda.
  5. Resultados y errores: elige métricas relacionadas con el problema, muestra una gráfica diagnóstica útil y analiza casos concretos de fallo. Explica la incertidumbre y las limitaciones de los datos. Evita elegir un procedimiento a partir de los resultados del conjunto final de prueba.
  6. Reproducibilidad: entrega un cuaderno que se ejecute desde un núcleo nuevo, entradas y semillas fijas, instrucciones sobre dependencias y un comando breve para reproducir el resultado. Indica dónde no se garantiza la reproducibilidad exacta en punto flotante.

Ampliaciones sugeridas

  • Fraude: compara un modelo probabilístico sin ponderación con un modelo ponderado de ordenamiento; deriva las implicaciones para el costo de las alertas y la interpretación de las probabilidades.
  • Texto: compara unigramas y bigramas conservando los grupos de familias de mensajes; examina errores y limitaciones del vocabulario.
  • Agrupamiento: estudia cómo la escala, la inicialización y el número de grupos afectan las asignaciones; explica si la interpretación permanece estable.
  • Pronóstico: compara persistencia estacional, un modelo autorregresivo lineal y XGBoost con los mismos orígenes móviles de predicción a un paso; explica cómo cambiaría la evaluación para pronosticar siete días desde un origen fijo.

Entrega opcional del software

Usa la lección 08 para guardar un pipeline ajustado y validar su recarga. La API proporcionada utiliza específicamente el esquema de abandono de clientes. Otro modelo requiere un esquema de solicitud, significado de respuesta, transformación de preprocesamiento y pruebas compatibles; no basta con sustituir el artefacto. El pronóstico necesita además una forma explícita de proporcionar o mantener el historial observado. Un comando de predicción por lotes sin conexión es una entrega válida cuando se adapta mejor a la tarea que un servicio HTTP.

Evaluación

Aplica la rúbrica docente: 30 % razonamiento matemático, 25 % diseño de validación, 25 % implementación legible y ejecutable, y 20 % interpretación. Un resultado negativo bien explicado puede obtener la máxima calificación. La mejor puntuación de prueba, por sí sola, no.
