Aprendizaje automático para matemáticos

Ocho lecciones prácticas que conectan probabilidad, optimización, álgebra lineal y razonamiento temporal con Python legible y un servicio de predicción funcional. Sigue 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08.

Requisitos: funciones y arreglos básicos de Python, álgebra lineal, derivadas, probabilidad condicional y estadística elemental. No se supone experiencia previa en aprendizaje automático. Todos los datos son pequeños, sintéticos, incluidos localmente y documentados en datasets.html. No se necesitan cuentas, API de pago, GPU ni descargas de datos externos.

¿Nuevo en bibliotecas de aprendizaje automático? Lee Tu primer experimento para conocer el vocabulario, las dimensiones de arreglos, la API de estimadores y una guía paso a paso del cuaderno.

Instalación inicial

Usa Python 3.11 o 3.12. En una terminal abierta en la raíz del repositorio:

python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e .
python -m ipykernel install --user --name mathematical-ml --display-name "Mathematical ML"
python -m jupyterlab

Si PowerShell bloquea la activación, usa .venv\Scripts\python.exe en lugar de python para cada comando; activar el entorno es opcional. En macOS/Linux actívalo con source .venv/bin/activate. En Jupyter selecciona el núcleo Mathematical ML . Los comandos posteriores suponen este entorno.

Ruta de estudio

Lección Pregunta Fundamento matemático Resultado práctico
01: Regresión ¿Cómo estimamos precios de viviendas? Riesgo empírico, mínimos cuadrados, regularización Un pipeline de preprocesamiento y regresión
02: Clasificación ¿Quién podría abandonar un servicio? Verosimilitud Bernoulli, regresión logística, costos de decisión Probabilidades y un umbral defendible
03: XGBoost ¿Pueden los árboles captar demanda no lineal? Modelos aditivos, gradientes funcionales, objetivos de árboles de segundo orden Experimento de boosting comparado con modelos de referencia
04: Aprendizaje con clases desbalanceadas ¿Cómo detectamos fraude poco frecuente? Prevalencia, precisión–exhaustividad, riesgo ponderado, costos de decisión Política de alertas seleccionada por validación
05: Clasificación de texto ¿Cómo dirigimos mensajes de soporte? Vectores TF-IDF dispersos, geometría coseno, verosimilitud multinomial Pipeline de clasificación de texto evaluado por familia de plantillas
06: Agrupamiento ¿Cómo segmentamos clientes sin etiquetas? Minimización de K-means, PCA, validación interna Grupos interpretables y diagnósticos de estabilidad
07: Pronóstico de series temporales ¿Cómo pronosticamos las ventas de mañana? Conjuntos de información, variables retardadas, evaluación con origen móvil Referencia estacional y pronósticos XGBoost a un paso
08: Despliegue ¿Cómo se convierte un modelo ajustado en servicio? Contratos estadísticos y de software, reproducibilidad Entrenamiento registrado y API de predicción validada

En cada lección, lee su README y ejecuta lesson.ipynb en orden. Cada lección conecta fundamentos matemáticos, opciones del software y ejemplos guiados. Lee la explicación, anticipa qué cambia un parámetro y examina el resultado calculado. Prevé unas 2–3 horas por lección, más tiempo para los ejemplos ampliados.

Sitio del curso

python scripts/build_site.py
python -m http.server 8000 --bind 127.0.0.1

Abre http://127.0.0.1:8000/site/. El sitio incluye teoría y código con resaltado de sintaxis, resultados capturados, ocho galerías, instrucciones y descargas de cuadernos. MathJax representa las matemáticas desde una CDN cuando hay conexión; los cuadernos locales son la referencia sin conexión. Pulsa Ctrl+C para detener el servidor. El sitio puede alojarse en GitHub Pages con el flujo de GitHub Actions incluido.

Verificar el curso

python -m pytest
python scripts/check_notebooks.py
python scripts/export_lesson_results.py
python scripts/build_site.py
python scripts/check_site.py

El ejecutor procesa las ocho lecciones guiadas con núcleos separados y escribe resultados en el directorio ignorado .verification/. Los cuadernos versionados mantienen las salidas vacías para que los estudiantes generen sus propias figuras. export_lesson_results.py copia las salidas verificadas a docs/results/ con hashes de código y datos y versiones de dependencias. Registra esas capturas después de modificar intencionalmente las lecciones; la construcción rechaza capturas desactualizadas. GitHub Pages usa resultados versionados y no ejecuta cuadernos Python. El flujo de verificación ejecuta cada cuaderno independientemente. Consulta las galerías.

Las últimas comprobaciones locales y sus limitaciones se registran en verification.md. Para validar el sitio después de reconstruirlo, ejecuta python scripts/check_site.py.

Ejecuta python scripts/check_data.py para comprobar que los generadores reproducen los bytes CSV versionados en el entorno actual sin sobrescribirlos. La reproducción exacta de bytes es más exigente que la equivalencia estadística y puede depender de las versiones de bibliotecas numéricas.

Reproducibilidad y docencia

Los CSV están versionados. Regenera todos los conjuntos con python scripts/generate_all_data.py solo cuando quieras actualizar las entradas de clase. generate_data.py regenera los datos originales de vivienda, abandono y bicicletas; los generadores adicionales pueden ejecutarse por separado. Cada conjunto tiene un modelo de muestreo documentado. Los intervalos de dependencias describen instalaciones compatibles; requirements-lock.txt registra el entorno de verificación. Para reproducir exactamente el entorno de clase instala ese archivo antes de python -m pip install --no-deps -e .. Las versiones fijadas corresponden al Python y la plataforma verificados; CI también comprueba una instalación nueva desde los intervalos declarados.

Las lecciones 04–07 no añaden dependencias. Texto usa variables TF-IDF dispersas locales; los embeddings preentrenados se discuten sin descargar modelos. Pronóstico usa datos realmente cronológicos y evalúa explícitamente predicciones móviles a un paso, a diferencia de los escenarios horarios independientes de la lección 03.

Consulta la guía docente para objetivos de aprendizaje, tiempos sugeridos y evaluación. Los modelos de datos están simplificados deliberadamente. Su desempeño no establece precisión real, causalidad, equidad ni preparación para producción. La API es un servicio didáctico local.

Termina con el proyecto del curso, que pide justificar un experimento completo y una entrega opcional de software. La API de despliegue sirve específicamente abandono de clientes; otras tareas necesitan su propio contrato de entrada.
