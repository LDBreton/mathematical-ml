Machine learning for mathematicians

Eight hands-on lectures connecting probability, optimization, linear algebra, and temporal reasoning to readable Python and a working prediction service. Follow 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08.

Prerequisites: basic Python functions and arrays, linear algebra, derivatives, conditional probability, and elementary statistics. No prior machine-learning experience is assumed. All datasets are small, synthetic, included locally, and documented in datasets.html. No accounts, paid APIs, GPU, or downloads of external data are needed.

New to machine-learning libraries? Read Your first experiment for vocabulary, array shapes, the estimator API, and a step-by-step notebook walkthrough.

Setup once

Use Python 3.11 or 3.12. In a terminal opened at the repository root:

python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e .
python -m ipykernel install --user --name mathematical-ml --display-name "Mathematical ML"
python -m jupyterlab

If PowerShell blocks activation, use .venv\Scripts\python.exe in place of python for every command; activation is optional. On macOS/Linux activate with source .venv/bin/activate. In Jupyter select the Mathematical ML kernel. All later terminal commands assume this environment.

Study route

Lecture Question Mathematical foundation Practical output
01: Regression How do we estimate house prices? Empirical risk, least squares, regularization A preprocessing and regression pipeline
02: Classification Who may leave a service? Bernoulli likelihood, logistic regression, decision costs Probabilities and a defensible threshold
03: XGBoost Can trees capture nonlinear demand? Additive models, functional gradients, second-order tree objectives A baseline-controlled boosting experiment
04: Imbalanced learning How do we detect rare fraud? Prevalence, precision–recall, weighted risk, decision costs A validation-selected alert policy
05: Text classification How do we route support messages? Sparse TF-IDF vectors, cosine geometry, multinomial likelihood A text classification pipeline evaluated by template family
06: Clustering How do we segment customers without labels? K-means minimization, PCA, internal validation Interpretable clusters and stability diagnostics
07: Time-series forecasting How do we forecast tomorrow's sales? Information sets, lagged features, rolling-origin evaluation Seasonal baseline and XGBoost one-step forecasts
08: Deployment How does a fitted model become a service? Statistical versus software contracts, reproducibility Tracked training and a validated prediction API

For each lecture, read its README and run lesson.ipynb in order. Each lesson connects mathematical foundations with software options and guided code examples. Read the explanation, predict what a parameter changes, then inspect the computed result. Plan roughly 2–3 hours per lecture, with additional time for the extended examples.

Course website

python scripts/build_site.py
python -m http.server 8000 --bind 127.0.0.1

Open http://127.0.0.1:8000/site/. The navigator includes syntax-highlighted theory and code, captured lesson outputs, eight executed-result galleries, lecture instructions, and notebook downloads. Math rendering uses MathJax from a CDN when online; the local notebooks remain the offline mathematics reference. Press Ctrl+C to stop the server. The generated website can be hosted through GitHub Pages using the included GitHub Actions workflow.

Verify the course

python -m pytest
python scripts/check_notebooks.py
python scripts/export_lesson_results.py
python scripts/build_site.py
python scripts/check_site.py

The notebook runner executes all eight guided lessons using separate kernels and writes results under ignored .verification/. The committed notebooks keep clean outputs so students generate their own figures. export_lesson_results.py copies checked lesson outputs into docs/results/ with source/data hashes and dependency versions. Commit those snapshots after intentional lesson updates; the site build rejects stale snapshots. GitHub Pages builds from committed snapshots and does not execute Python notebooks. The verification workflow independently executes every notebook. See the galleries.

The latest local checks and their limitations are recorded in verification.md. To validate the website after rebuilding, run python scripts/check_site.py.

Run python scripts/check_data.py to check that the generators reproduce the committed CSV bytes in the current environment without overwriting them. Exact byte reproduction is a stronger condition than statistical equivalence and may depend on numerical-library versions.

Reproducibility and teaching

CSV fixtures are committed. Regenerate all fixtures with python scripts/generate_all_data.py only when intentionally updating the classroom inputs. generate_data.py regenerates the original housing, churn, and bike data; the extension generators can be run separately. Each dataset has its own documented sampling model. Dependency ranges describe compatible installations; requirements-lock.txt records the environment used for verification. For an exact classroom environment install that file before python -m pip install --no-deps -e .. Lock versions target the verified Python version and platform; CI additionally checks a fresh installation from declared ranges.

Lectures 04–07 add no dependencies. Text classification uses local sparse TF-IDF features; pretrained embeddings are discussed without requiring model downloads. Forecasting uses genuine chronological data and explicitly evaluates rolling one-step predictions, unlike the independent hourly scenarios in lecture 03.

See instructor guide for learning outcomes, suggested timing, and assessment. Data models are deliberately simplified. Performance on these fixtures does not establish real-world accuracy, causal effects, fairness, or production readiness. The API is a local teaching service.

Finish with the course project, which asks you to justify a complete experiment and an optional software handoff. The deployment API serves churn specifically; other tasks require their own input contract.
